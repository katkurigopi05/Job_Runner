# 500 paraphrased questions for testing the job database

Written 2026-11-03 for testing the posting database and the assistant's search with AI agents.
Each question was written from one open posting, so every question has a known right answer:
that posting. An agent asks the question and records where the posting lands in what comes back.

## How the questions were written

- **One posting each, 500 postings.** Drawn read-only from the 16,249 open postings that have text
  and Qwen vectors, kept to the search area by `locality.area_exclusion` (strict reading, so a
  location it cannot place is left out), one per title and company, spread across job families
  with a fixed seed (20261103). 231 employers.
- **Paraphrased.** A question describes the work and the kind of employer. It does not use the
  posting's title, the company's name, or the name of a product or technology. Words such as
  "remote", a city, or a level ("entry-level", "doctoral") appear where the posting says them.
- **Every question passes the search gate.** Each contains a word from `retrieve._POSTING_WORDS`
  (jobs, roles, positions, openings, listings, hiring, company …), so the assistant searches.
- **No question names a hiring company by accident.** All 500 were run through the assistant's
  own company reader (`retrieve._named_companies`). 15 wordings were read as naming an employer
  ("front desk" as Front, "at scale" as Scale AI) and were reworded; the originals are kept in
  Appendix A as tests of that reader.
- **Known-item, not graded.** Other postings can answer a question as well as its target. A miss
  says the target was not found, not that the answer was wrong. 24 targets have a near-twin from
  the same employer (the same job in another city, say), listed in the Twins column.

## How an agent runs it

1. **Check the target is still open.** Postings close and are pruned after 30 days. Skip a closed
   target (`postings.closed_at IS NOT NULL`, or the id is gone) and count it as skipped, not missed.
2. **Ask the question exactly as written**, through one of:
   - the assistant: `POST http://127.0.0.1:8000/chat` with `{"question": "…"}`. The five postings
     shown are `sources` and the rest of the list is `more_sources`, in order;
   - the MCP tool `search_postings`, or the agent's own search over the database.
   Say which one was used. The search runs on this machine; the questions hold no personal data.
3. **Record the target's rank**: its position in `sources` then `more_sources` (1 = first), or
   "not listed". Match on the posting id or the URL. Record a twin's rank separately.
4. **Score.** Hit@5 (target among the five shown), Hit@listed (anywhere in the list), MRR, and the
   median seconds a question. Report them overall and by family, strict and with twins.
5. **Compare modes, if testing search changes.** Run the set with the shipped search and with
   `CHAT_QWEN_SEARCH=true` + `CHAT_SEMANTIC_CANDIDATES=true` (restart `make api` between runs).

Read-only throughout: an agent running this writes nothing to the database, grades nothing for
the owner, and does not re-arm the crawler.
