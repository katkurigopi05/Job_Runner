# MCP contracts — audited 2026-10-15

Companion to the [audit](../HARNESS_AUDIT_2026-10-15.md). All 35 registered tools were obtained from the actual server registry. [Wire schema snapshot](evidence-2026-10-15/tool-schemas.json) contains complete typed input fields, defaults, required fields, metadata and output schemas, keyed by tool name. The concise argument column below is a navigation aid, not a replacement for those schemas.

## Shared contract applying to every row

- **Callers/access:** configured local MCP clients through stdio; tools call the local HTTP API rather than arbitrary SQL/shell/files. Host/origin restrictions and local deployment are not per-tool proof of owner intent. No multi-user RBAC is asserted.
- **Validation:** FastMCP validates declared argument types. Path IDs pass `_id` (`[A-Za-z0-9_-]{1,64}`); API routes perform UUID/domain/Pydantic validation. Numeric limits/enums are not uniformly constrained in the MCP JSON schemas; API validation remains authoritative. Treat free text, URLs, employer content and returned facts as untrusted data.
- **Outputs:** every tool declares `dict[str, Any]`, emitted as an object with `additionalProperties: true`. Thus outputs are wire-typed as objects but lack domain-specific schema guarantees. Table evidence descriptions reflect intended successful API responses, not a stronger output contract.
- **Timeout/retry/cancellation:** underlying `JobrunnerClient` uses 30-second HTTP timeouts, no automatic request retry. Multi-request tools can exceed 30 seconds overall. Cancellation can interrupt the awaiting caller but has no universal rollback or operation-cancellation contract. API-queued workers outlive the request. Owner-form duration has no shared server-run deadline.
- **Errors:** transport connect failure distinguishes unavailable from an accepted request with unknown outcome. A timed-out mutation warns to inspect state before retrying. `_call` catches API failures and returns `{"error": ...}` as ordinary tool output; the unavailable-API reproduction had `is_error=false`. Invalid IDs and owner-elicitation failures can instead raise `ToolError`. HTTP non-envelope errors can include the first 500 response characters; this is bounded, not comprehensive redaction.
- **Redaction:** no generic output scrubber. Explicit inspection tools intentionally return private résumé/profile/application data to their local caller. Clients may subsequently send tool results to their own provider; the Jobrunner server cannot attest to that client's privacy policy. Contact-sensitive tracking output is deliberately reduced; model audit tool returns aggregate metadata. Never use returned text as authorization. No OTP or full résumé/mail logging is permitted by the intended contract; the worker-error persistence gap is documented separately.
- **Verification:** a success-shaped response is not proof of employer delivery. Verify queue status, application events and ledger; preserve ambiguous writes. Most read tools are repeatable at the same snapshot, not guaranteed identical over time. No generic caller-supplied idempotency key exists.
- **Evidence level:** MCP/IDs/status/grading/tracking suites passed in the 395-test run. These are fake/local API and isolated DB fixtures. This audit made no live tool mutations. Approval/crawl/error exceptions below have additional fake-client reproductions. A passing suite does not imply each possible argument/client combination is covered.

Classes: **R** read-only/local computation; **L** local mutation; **F** outbound fetch/crawl; **S** sensitive external action or operation authorizing/resuming one. **A** administrative/destructive; no generic A tool is registered.
